## **Project 1 (Rank \#1): itch-xsk — NASDAQ TotalView-ITCH 5.0 & MoldUDP64 Feed Handler, Gap-Recovery Engine, and Cache-Optimal L3 Order Book**

### **A. Project Identity**

**itch-xsk** is a deterministic, Linux-native C++20/23 market data feed handler and full-depth Level-3 (L3) order book reconstruction engine implementing two authentic exchange wire specifications: **NASDAQ MoldUDP64 v1.00** for UDP packet framing, message sequencing, heartbeats, and gap retransmission, and **NASDAQ TotalView-ITCH 5.0** for binary order-lifecycle updates39. Alongside the feed handler, you build an open-loop historical packet replayer that memory-maps real multi-gigabyte NASDAQ ITCH 5.0 binary files4, packs messages into compliant MoldUDP64 datagrams, injects deterministic packet drops and microbursts across a Linux virtual Ethernet (veth) pair, and benchmarks three swappable Linux ingestion backends—recvmmsg with SO\_BUSY\_POLL, io\_uring, and AF\_XDP—driving a zero-allocation L3 order book6.  
In production HFT infrastructure, the market data feed handler sits at the most latency-critical boundary between the exchange network and internal pricing models10. Citadel Securities explicitly states in its Market Data Engineer specification that market data correctness, determinism, throughput, and latency directly govern trading performance and P\&L, naming ITCH among core exchange protocols10. itch-xsk tackles three real production problems simultaneously: reducing kernel-to-userspace delivery overhead and tail jitter during market-open microbursts6, maintaining exact sequence integrity across duplicated A/B UDP streams when packets drop or arrive out of order40, and tracking millions of live orders with minimal L1/LLC/dTLB misses and zero hot-path dynamic memory allocation1.

### **B. Why an HFT Interviewer Should Care**

Inspecting itch-xsk allows a principal engineer to verify concrete systems skills directly in source code and profiler traces. They can verify whether you parse big-endian binary protocols safely without strict-aliasing undefined behavior (using std::memcpy / std::bit\_cast and std::byteswap), handle fixed-point integer prices (Price(4), representing implied 4 decimal places up to 200,000.0000 rather than floating-point doubles)39, understand the Linux receive path (sk\_buff allocation and NAPI polling versus eBPF XDP redirection into AF\_XDP UMEM rings)6, and engineer cache-sympathetic memory layouts verified by hardware counters1.  
Compared with typical student GitHub "order book" repositories—which almost universally synthesize CSV or in-memory random orders, store levels in std::map\<double, std::list\<Order\>\>, ignore wire framing and packet loss, and report a single average throughput figure—itch-xsk demonstrates production discipline across networking, data structures, fault recovery, and statistical latency measurement.

### **C. Technical Architecture**

The deployment model isolates two physical CPU cores (isolcpus, nohz\_full, rcu\_nocbs) on a single Linux host so both the open-loop replayer and the feed handler read the exact same invariant hardware clock (RDTSCP) without cross-machine clock skew6.  
![][image1]  
**Open-Loop MoldUDP64 Replayer (Core 1):** The publisher memory-maps a downloaded NASDAQ TotalView-ITCH 5.0 archive (mmap with MADV\_SEQUENTIAL) and frames variable-length ITCH messages into compliant MoldUDP64 Downstream Packets: a 20-byte header (Session\[10\], SequenceNumber\[8\], MessageCount\[2\], where 0 signals a heartbeat and 0xFFFF signals end of session) followed by packed \[2-byte MessageLength\]\[MessageData\] blocks40. It supports constant-rate open-loop pacing (eliminating coordinated omission)6 alongside time-compressed historical burst replay (replaying real market-open bursts at 1×, 5×, or 10× speed). In benchmark mode, it embeds a transmit RDTSCP cycle stamp, duplicates traffic across Feed A and Feed B streams over Linux veth pairs50, injects configurable packet drops or reorderings, and runs a MoldUDP64 retransmission responder serving Request packets40.  
**Swappable Linux Networking Backends (Core 2):** Three ingress engines sit behind a compile-time C++20 concept policy—eliminating virtual dispatch overhead on the packet-receive loop33. Backend A (recvmmsg \+ SO\_BUSY\_POLL) amortizes syscall transitions across batches while still traversing the full kernel sk\_buff \-\> IP \-\> UDP \-\> socket queue chain6. Backend B (io\_uring) leverages shared submission and completion rings with registered fixed buffers to evaluate asynchronous kernel I/O against busy-polled sockets6. Backend C (AF\_XDP \+ eBPF) attaches a minimal eBPF XDP filter to the veth interface that checks UDP destination ports and calls XDP\_REDIRECT into an AF\_XDP socket (XSK) backed by four shared-memory rings (Fill, RX, TX, Completion) and fixed-frame UMEM6. On veth, AF\_XDP operates in copy mode at ₹0; on an optional desktop Intel NIC supporting igc or ixgbe, the identical userspace ring code switches directly to zero-copy DMA6.  
**A/B Arbitrator, Gap Recovery, and Branchless ITCH 5.0 Decoder:** The arbitrator tracks next\_expected\_seq. Whichever redundant feed delivers seq \== next\_expected\_seq first immediately advances the decoder; trailing duplicates (seq \< next\_expected\_seq) drop in O(1). When both feeds drop a packet (seq \> next\_expected\_seq), incoming future packets stage inside a pre-allocated out-of-order ring buffer while a MoldUDP64 Request Packet (Session\[10\], FirstSeq\[8\], RequestedMessageCount\[2\]) requests retransmission from the replay server40. Validated payloads enter a branchless ITCH 5.0 decoder supporting core order-lifecycle and market-state messages: System Event (S), Stock Directory (R), Add Order (A), Add Order with MPID (F), Order Executed (E), Order Executed with Price (C), Order Cancel (X), Order Delete (D), Order Replace (U), Trade (P), Cross Trade (Q), and Net Order Imbalance Indicator (I)39. Byte-order conversion relies on std::byteswap (C++23) or \_\_builtin\_bswap64, dispatched via a flat table indexed by message-type byte to minimize indirect branch mispredictions.  
**Cache-Optimal L3 Order Book, Memory Strategy, and OS Tuning:** All hot-path state lives in pre-allocated contiguous memory backed by mmap with 2 MiB HugePages (MAP\_HUGETLB or MADV\_HUGEPAGE) and locked via mlockall(MCL\_CURRENT \| MCL\_FUTURE) to eliminate runtime page faults and shrink dTLB pressure1. Each OrderNode fits inside a single 64-byte cache line and uses 32-bit slab indices (halving pointer footprint relative to 64-bit raw pointers) for intrusive doubly-linked FIFO queues within each price level. Order lookups by 64-bit OrderReferenceNumber run through a pre-sized, power-of-2 open-addressing flat hash map (linear or Robin-Hood probing with backward-shift deletion to avoid tombstone accumulation during long sessions). Price levels per symbol use a hybrid dense tick-array anchored around the active Best Bid/Offer (BBO) with a sparse overflow map for deep far-from-market quotes, paired with a compact bitset scanned via std::countl\_zero / TZCNT to locate the next active best price level in O(1). The feed-handler thread executes strictly single-threaded—no mutexes, no locks, no dynamic allocation—pinned to an isolated physical core (pthread\_setaffinity\_np) with SMT disabled or sibling cores left idle42.

### **E. Benchmarking and Validation Plan**

A pervasive flaw in amateur low-latency benchmarks is reporting averages or quiet-period medians, or using a closed-loop harness where the sender pauses while waiting for the receiver (**coordinated omission**)8. Real trading systems fail during microbursts. An industry latency engineering analysis of the U.S. Options Price Reporting Authority (OPRA) multicast expansion illustrates why median metrics are deceptive: expanding from 48 to 96 multicast lines barely budged P50 median latency, yet collapsed P99 tail latency by nearly 90%8.  
![][image2]  
**Correctness, Stress Testing, and Ablation Methodology:** Validate book correctness by differentially replaying a complete trading day of authentic NASDAQ ITCH 5.0 binary data—such as 12302019.NASDAQ\_ITCH50.gz (\~3.52 GB compressed) or 01302020.NASDAQ\_ITCH50.gz (\~5.60 GB compressed)4—through both the reference std::map book and your optimized slab book, asserting identical L1/L2 snapshots and volume invariants on every update. Follow this with a bursty packet-loss stress test injecting 1% packet drops and reordering across A/B feeds to prove exact convergence. For performance, execute a strict 2×3 ablation matrix comparing (Naive std::map Book vs. Cache-Optimal L3 Book) across (recvmmsg+busy-poll vs. io\_uring vs. AF\_XDP copy mode), paired with an in-process decode-plus-book microbenchmark separating CPU/cache improvements from kernel networking latency.  
**Latency, Throughput, and Hardware-Counter Profiling:** Drive the benchmark using an **open-loop load generator** paced across stepped message rates (modeled on multi-rate Linux networking stack evaluations from 20k up to peak sustainable msgs/sec)6, recording every latency sample into **Gil Tene's HdrHistogram** to extract **p50, p90, p99, and p99.9** wire-to-book-update percentiles8. Isolate and report worst-burst windows (such as the 09:30:00 US market open in the ITCH stream) rather than diluting spikes across a full session8. Pair every run with perf stat \-e cycles,instructions,branches,branch-misses,L1-dcache-load-misses,LLC-load-misses,dTLB-load-misses, peak RSS memory usage, page-fault counts (verifying zero major and minor page faults post-warmup), and /proc/interrupts verification on isolated cores1. Where an Intel CPU and free Intel VTune Profiler are available, add a microarchitecture exploration report to quantify front-end vs. back-end memory-bound stalls.  
**Consumer Hardware Validity Boundaries:** Document explicitly in your README which measurements are scientifically meaningful on consumer hardware and which are not. Relative speedups between std::map and intrusive slab structures, LLC/dTLB/branch-miss reductions, relative syscall and buffer-copy overhead across recvmmsg, io\_uring, and AF\_XDP on veth, and tail-jitter reduction under isolcpus \+ disabled Turbo Boost are fully valid52. Conversely, absolute veth microseconds cannot be compared to colocated FPGA/10GbE hardware-timestamped wire latency, and AF\_XDP copy mode over veth does not measure physical NIC DMA latency6.

## **Project 2 (Rank \#2): shmbus-mc — Formally Verified Lock-Free Shared-Memory IPC, Event-Sourced Sequencer, and Hardware-Traced Telemetry Engine**

### **A. Project Identity**

**shmbus-mc** is a C++20/23 ultra-low-latency inter-process communication (IPC) library and deterministic event-sourced sequencer built over POSIX shared memory (shm\_open / mmap with HugePages). It implements three foundational HFT concurrency primitives: (1) a wait-free **Single-Producer Single-Consumer (SPSC)** ring buffer with cached remote indices and 128-byte false-sharing isolation41, (2) a **Single-Producer Multi-Consumer (SPMC)** broadcast ring supporting both lossless backpressure and non-blocking overwrite/epoch subscribers alongside a wait-free **SeqLock** snapshot channel, and (3) a **Deterministic Sequencer & Append-Only Binary Journal** that stamps commands into a single total order and writes asynchronously off the critical path so crashed downstream engines reconstruct identical state from byte zero19.  
What elevates shmbus-mc into rare territory is its verification and observability stack: every lock-free atomic path is **exhaustively bounded-model-checked under weak memory models (RC11 and IMM) using GenMC**5, audited for cross-core MESI cache-line transfers with **Linux perf c2c**, and instrumented with a cold-path **Intel Processor Trace (magic-trace)** snapshot trigger that captures \~30 ns hardware execution timelines whenever a p99.9 tail-latency spike breaches threshold13. In real HFT systems, firms avoid mutex contention on the hot path by isolating single-threaded stages (feed handler \-\> strategy \-\> risk gateway \-\> logger) communicating over lock-free shared-memory rings and a deterministic sequencer19. Citadel Securities explicitly emphasizes explicit, replayable state transitions for recovery19, while Optiver highlights concurrent data structures as central to nanosecond-scale C++ design14.

### **B. Why an HFT Interviewer Should Care**

Lock-free concurrency and C++ atomic memory orderings are among the sharpest technical filters in HFT interviews—and the domain where surface-level candidates are exposed fastest30. Because x86-64 hardware enforces Total Store Order (TSO), a subtly broken C++ ring buffer using memory\_order\_relaxed where acquire/release is required will frequently survive millions of stress-test iterations without failing, only to break under aggressive compiler reordering or weak-memory ARM64 CPUs5. By compiling your C++20 synchronization primitives via Clang to LLVM IR and verifying bounded multi-threaded clients exhaustively under **RC11 and IMM with GenMC**5, you provide rigorous verification against weak-memory ordering bugs and data races. Pairing that formal audit with perf c2c HITM (Hit in Modified state) cache-contention measurements—proving why 64-byte alignment can still trigger false sharing under 128-byte spatial cache prefetching41—and magic-trace root-cause captures of actual OS jitter13 demonstrates principal-level systems mastery.

### **C. Technical Architecture**

shmbus-mc is structured into two strictly decoupled planes. In the **Runtime Shared-Memory IPC Plane**, Core 1 hosts the Producer and Deterministic Sequencer writing into a single HugePage-backed shared-memory region subdivided into three physically separated cache-isolated zones: a 128-byte-padded Write Cursor strip, a 128-byte-padded Read Cursors strip, and a power-of-two contiguous Data Slot Array. Core 2 runs an SPMC Strategy Reader pinned to an isolated core and hooked to a cold-path Intel PT tail-latency trigger, while Core 3 runs an asynchronous Journal Writer draining the same shared-memory ring into an append-only binary replay log. In the **Formal Verification & Contention Audit Plane**, the exact same C++20 atomic ring headers are compiled through Clang to LLVM IR and fed into the GenMC verifier under RC11 and IMM memory models, while cross-core stress loads are profiled continuously with perf c2c and HdrHistogram5.  
**Wait-Free SPSC Ring Buffer (SpscRing\<T\>):** Enforces power-of-2 capacity (index & (N \- 1)) and static\_assert(std::is\_trivially\_copyable\_v\<T\>) so cross-process shared-memory transport remains free of object-lifetime or vtable pointer corruption. Following Erik Rigtorp's ring-buffer optimizations41, write\_idx\_ and read\_idx\_ sit on distinct **128-byte aligned boundaries** (alignas(128)) to neutralize adjacent-cache-line prefetching false sharing41. Each endpoint maintains a thread-local cached copy of the peer's cursor (cached\_read\_idx\_ on producer, cached\_write\_idx\_ on consumer), issuing an acquire atomic load of the shared cursor only when its local cached bound appears full or empty—sharply reducing cross-core cache invalidations42. All hot-path operations use minimal C++20 orderings (relaxed for self-index loads, release for publishing writes/reads, acquire for observing remote progress) and never memory\_order\_seq\_cst5.  
**SPMC Broadcast Ring, SeqLock, and Event-Sourced Sequencer:** SpmcRing\<T\> supports multiple independent processes mapped into the shared segment under two policies: a *Backpressure Mode* (producer throttles to the slowest active consumer cursor) for lossless journaling/risk stages, and an *Overwrite/Epoch Mode* (monotonic 64-bit sequence tag per slot enabling slow market-data consumers to detect wrap-around and resynchronize cleanly). SeqLock\<T\> provides wait-free single-writer, multi-reader publication of latest BBO or risk parameters via odd/even version counters and chunked atomic payload loads with std::atomic\_thread\_fence ordering—offering an ideal second target for GenMC verification. The Deterministic Sequencer assigns strictly monotonic 64-bit sequence numbers and RDTSCP timestamps to every inbound command44, while the off-critical-path Journal Writer persists committed records in batches (O\_DIRECT or mmap flush) so any crashed downstream engine rebuilds bit-for-bit identical state strictly by replaying the input log19.  
**HugePage/NUMA Memory Strategy and Hardware Diagnostics:** Shared-memory segments are backed by shm\_open/memfd\_create with explicit 2 MiB MAP\_HUGETLB (falling back to MADV\_HUGEPAGE), pre-faulted across all pages at startup, and pinned via mlock() to prevent runtime page-fault stalls13. Optional libnuma (mbind) topology detection binds pages to local NUMA nodes on multi-socket servers while degrading cleanly on single-socket laptops1. For formal validation, bounded multi-threaded C++20 harnesses compile via Clang to LLVM IR and execute genmc \--rc11 and genmc \--imm5, paired with a deliberately broken memory\_order\_relaxed test branch documenting GenMC's DOT counterexample graph catching a race that passes x86-64 stress runs5. For live tail-spike attribution, a cold-path snapshot hook invokes Intel Processor Trace (magic-trace, \~30 ns timing accuracy with typically under 5–10% overhead in circular buffer mode) whenever an IPC hop crosses a p99.9 latency threshold13.

### **C. Technical Architecture**

The execution gateway and historical simulator share a single deterministic event interface so identical risk, state-machine, and strategy-hook code executes in both historical replay and socket gateway tests—mirroring production quantitative-development architecture7.  
![][image3]  
**Compile-Time (constexpr) OUCH 5.0 Codec:** Encodes and decodes NASDAQ OUCH 5.0 variable-length binary messages (UserRefNum, side, quantity, symbol, fixed-point price, time-in-force, display flags, and optional append tags)38. **AVX2 SIMD Pre-Trade Risk Firewall:** Per-symbol risk states (net position, pending open buy/sell quantities, max position limit, max order notional, BBO fat-finger price collar bounds, and kill-switch flags) are packed into 32-byte-aligned **Structure-of-Arrays (SoA)** buffers. On every outbound order, four parallel 64-bit limit comparisons execute branchlessly via AVX2 intrinsics (\_mm256\_cmpgt\_epi64 \+ \_mm256\_movemask\_epi8)—with an optional AVX-512 path where supported and a portable scalar fallback for non-AVX2/ARM64 machines—producing a single bitmask reject code with zero unpredictable branches on the healthy accept path1. Explicit state-transition tables govern every order lifecycle state (PENDING\_NEW, LIVE, PENDING\_REPLACE, PENDING\_CANCEL, PARTIAL, FILLED, CANCELED, REJECTED), resolving race conditions—such as an Executed report arriving while a Cancel is in flight—and supporting deterministic disconnect reconciliation so orders are neither duplicated nor lost19.  
**Queue-Aware Historical Exchange Simulator (Market Realism):** Rather than assuming instant fills at historical touch prices, outbound OUCH messages and inbound ITCH updates pass through a deterministic timing-wheel delay queue parameterized by configurable one-way latency profiles (for example, 1 µs, 10 µs, 50 µs, and 200 µs). When a simulated resting limit order joins price P, the engine snapshots the exact historical L3 resting volume ahead of it (qty\_ahead) from the ITCH stream; subsequent historical executions at P decrement qty\_ahead, while historical cancellations at P apply explicit conservative (back-of-queue) versus pro-rata cancel-attribution assumptions rather than optimistically assuming every cancellation occurs ahead of your order. The ledger tracks realistic maker/taker fee schedules, multi-level crossing slippage for aggressive orders, and post-fill adverse-selection markouts. A simple deterministic strategy hook (such as an inventory-skewed BBO quoter) exists solely to generate realistic order/cancel/replace traffic and measure fill-rate sensitivity to latency—accompanied by an explicit documentation section explaining why historical replay cannot capture live participant reaction or true market impact, and why simulated PnL never proves a viable live strategy.
